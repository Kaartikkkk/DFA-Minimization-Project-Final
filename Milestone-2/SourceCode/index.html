      Overview

      Why DFA minimization matters

      Many DFAs have duplicate or unnecessary states that do the exact same thing. Minimizing a DFA finds these matching states and combines them together, creating the smallest machine that accepts the exact same language.

      Step-by-Step Visualizer

      Watch every single step with live state diagrams and working tables so you always understand why a state was merged or removed.

      Two Standard Algorithms

      Supports both Table-Filling (Myhill-Nerode) and Partition Refinement (Moore), with cross-comparison to confirm they match.

      Automated Verification

      Automatically verifies that the original and minimized DFAs accept and reject the exact same strings on hundreds of sample words.

      Zero Installation

      Built with pure HTML, CSS, and modern JavaScript. Opens instantly in any web browser without servers or setup.

      How Minimization Works

      A simple 4-step walkthrough

      Phase 1

      Remove Unreachable States

      Starts at the initial state and visits all reachable states. Any state that cannot be reached is discarded.

      Phase 2

      Find Matching States

      Compares state pairs. States that produce identical outcomes on all symbols are marked as equivalent.

      Phase 3

      Merge State Groups

      Combines equivalent states into single composite states, rewiring all transitions cleanly.

      Phase 4

      Verify Equivalence

      Tests strings through both machines to mathematically verify that the minimized DFA accepts the exact same language.
